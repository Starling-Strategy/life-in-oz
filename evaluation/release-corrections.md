# Reference corrections in v1.0.0

A release review read all 53 documents and all 156 reference experiences. It found two reference-summary problems. The source documents and all 326 stored evidence quotations, contexts and offsets remain unchanged.

## Iris's callback windows

- Person: `m021`
- Episode: `m021-home-care-callback-windows`
- Source: [Kitchen Notes and Call Windows](../sources/ozx-05-04-email-thread.txt), blocks `b002` and `b004` in the matching JSON.

The original reference summarized the earlier message, in which Iris leaves one request pending. A later reply says "All confirmed now" without naming that request. The revised summary says the request was **initially** left pending and explicitly preserves the ambiguity about its final status. Do not grade a tool against an unqualified assertion that the request is still pending, or that the specific request was definitely resolved.

The stored evidence anchors cover the earlier account in `b002`. Read `b004` as well when evaluating final-status claims; the existing anchors do not by themselves establish the whole thread's outcome.

## Elena's timetable check

- Person: `m041`
- Episode: `m041-community-performance-bus-notice`
- Source: [Notes on getting people across without the parade](../sources/ozx-03-05-manager-conversation.txt), block `b001` in the matching JSON.

The original summary retained a caveat about a "departure-log method" that the current source does not use. The source explicitly describes checking the current timetable and service notices. The revised summary removes that stale criticism and names the method actually present in the document.

These are agent editorial corrections, not independent human certification of the annotation set. They illustrate why a mechanically valid quote and a reliable interpretation are different checks.
